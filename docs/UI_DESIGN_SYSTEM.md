# PlayScout UI 设计规范

版本：1.0  
适用范围：公开网站、编辑后台、桌面端与移动端

## 1. 设计目标

PlayScout 的页面需要同时表达四个特征：可信的数据、可快速执行的攻略、丰富的游戏覆盖和持续更新的内容。视觉上保持清晰、克制和高信息密度，不使用新闻门户常见的拥挤边框与无层级卡片堆叠。

## 2. 设计原则

1. 先展示答案，再展示解释和来源。
2. 数据、编辑观点和玩家观点使用不同标签。
3. 每个内容卡片至少回答“是什么、属于哪款游戏、何时更新”。
4. 重要页面首屏至少提供两个可继续浏览的方向。
5. 长列表支持筛选、排序和分页，不能只依赖无限滚动。
6. 广告与赞助内容不得模拟榜单、攻略按钮或系统状态。

## 3. 设计令牌

### 3.1 颜色

```css
--color-ink: #0d1723;
--color-navy-900: #12283d;
--color-navy-800: #19354d;
--color-paper: #ffffff;
--color-surface: #f2f5f6;
--color-line: #dfe5e8;
--color-muted: #647282;
--color-lime: #c9f24b;
--color-cyan: #58c8d1;
--color-teal: #4b9ba2;
--color-violet: #8b79f7;
--color-orange: #ff764d;
--color-success: #159963;
--color-warning: #bd7612;
--color-danger: #d7514a;
```

语义规则：

- 荧光绿用于主要操作、当前选项和可信更新提示。
- 青绿色用于数据标签与来源。
- 橙色用于新闻、评测或需要注意的内容类型。
- 红绿排名变化必须同时显示箭头或文字，不能只依赖颜色。
- 深色背景只用于导航、视频区和重点游戏头图。

### 3.2 字体

- 标题：Manrope，系统回退 `Arial, sans-serif`。
- 正文：DM Sans，系统回退 `Arial, sans-serif`。
- 数字和兑换码：支持等宽数字；兑换码使用系统等宽字体。
- 正文字号桌面 16px、移动端 16px，行高 1.6。
- 页面 H1：桌面 40–52px，移动 30–36px。
- 区块 H2：桌面 26–32px，移动 23–27px。
- 卡片标题：16–22px，根据卡片层级选择。
- 辅助信息不得小于 12px。

### 3.3 间距

采用 4px 基础网格。常用值：4、8、12、16、20、24、32、40、48、64、80。

- 卡片内边距：紧凑 12–16px，标准 20–24px。
- 区块间距：桌面 56–72px，移动 36–48px。
- 列间距：桌面 20–28px，移动 12–16px。

### 3.4 圆角与阴影

- 小控件：6–9px。
- 普通卡片：12–15px。
- 重点视觉：16–20px。
- 图标根据商店图标形状使用 20%–23% 圆角。
- 默认卡片使用边框，不滥用阴影。
- 浮层阴影：`0 24px 70px rgba(13, 23, 35, .20)`。

### 3.5 布局

- 最大内容宽度：1220px。
- 桌面页边距：至少 24px；移动端：12–16px。
- 文章正文最大宽度：760px。
- 内容页右栏：280–340px。
- 首页首屏：主专题 50%、今日更新 22%、榜单 28%。
- 12列网格；常用内容布局为 8+4、7+5、6+3+3。

## 4. 核心组件

### 4.1 Header

两层结构：

1. 趋势条：趋势词、数据更新时间、地区选择。
2. 主导航：Logo、Games、Rankings、Guides、News、Videos、Codes、搜索。

桌面端主导航始终可见；移动端显示 Logo、搜索和菜单按钮。移动菜单包含全部一级频道、平台入口和热门游戏。

### 4.2 内容卡片

卡片至少包含内容类型、标题、游戏名称或主题，以及发布时间或最后验证时间。状态包括 default、hover、focus、loading skeleton、empty 和 error。

### 4.3 游戏卡片

- 48–64px 游戏图标。
- 名称、平台和分类。
- 一项核心状态：排名、评分、新上线或更新。
- 点击进入唯一游戏中心 URL。

### 4.4 榜单行

- 名次宽度固定。
- 游戏图标、名称和发行商为一个点击区域。
- 排名变化同时显示符号与数值。
- 桌面显示趋势、最高排名和上榜时长；移动端收起次要字段。
- 表头在长列表滚动时保持可见。

### 4.5 视频卡片

- 16:9 缩略图、播放图标和时长。
- 标题、游戏、频道、发布日期和验证标签。
- 点击具体视频或站内视频详情，不得跳转到搜索页。
- 外链使用外部链接图标和新标签页。

### 4.6 来源与验证

统一 `SourceBadge` 和 `FreshnessBadge`：Official source、Player tested、Editor verified、Updated today、Needs review、Expired。悬浮或点击后显示来源名称、时间和适用版本。

### 4.7 筛选器

- 桌面端可以使用横向工具栏或左侧筛选栏。
- 移动端使用底部抽屉。
- 已选条件显示为可删除 chip，并提供 Clear all。
- 改变筛选条件时同步 URL，并公告结果数量变化。

### 4.8 分页

频道、游戏库和榜单使用可抓取分页。显示上一页、下一页、当前页和必要的邻近页。移动端可以同时提供“加载更多”，但不能替代可访问分页 URL。

### 4.9 广告位

- 顶部横幅：桌面最大 970×250，移动端自适应。
- 正文广告与上下正文至少保持 24px 距离。
- 右栏广告不得覆盖粘性游戏导航。
- 所有广告显示 Advertisement 或 Sponsored。
- 广告加载失败时收起空白区域。

## 5. 页面模板

### 5.1 首页

首屏三栏，随后至少六个内容区块。桌面首屏建议显示 10–14 个可点击内容入口；移动端前两个屏幕至少显示主专题、榜单入口和 4 条更新。

### 5.2 频道列表

结构：频道头部、特色内容、筛选/子频道、主列表、热门侧栏、分页。每页首批服务端输出至少 20 条内容。

### 5.3 游戏库

结构：标题和统计、搜索、筛选、排序、游戏网格、分页。桌面每行 3–4 张卡片，移动端每行 1–2 张。

### 5.4 游戏中心

结构：游戏头部、粘性子导航、Start here、攻略组、榜单、活动、兑换码、视频、玩家技巧、相关游戏和来源。

### 5.5 文章详情

结构：面包屑、类型、标题、摘要、作者与验证信息、快速答案、目录、正文、素材、来源、更新记录、相关内容。

### 5.6 榜单详情

结构：标题、数据时间、榜单含义、筛选、榜单表、趋势说明、方法与来源、相关攻略。

### 5.7 编辑后台

使用更紧凑的中性界面。左侧导航、顶部全局搜索、内容主体和右侧状态栏。危险操作使用红色且需要明确文本。

## 6. 响应式规则

- ≥1200px：完整三栏和桌面导航。
- 768–1199px：两栏；今日更新移到首屏下方。
- <768px：单栏；主专题、实时榜单、今日更新依次排列。
- 榜单和复杂数据表允许横向滚动，并保留第一列。
- 粘性元素不能占用超过移动视口高度的 18%。
- 横向游戏轨道需要显示下一项的一部分，提示可以继续滑动。

## 7. 动效

- 常规反馈 120–180ms，页面区域切换 180–240ms。
- 动效使用 opacity、transform，避免引发布局变化。
- 支持 `prefers-reduced-motion`。
- 榜单更新时只突出变化行，不整表闪烁。

## 8. 文案规范

- 标题直接描述用户结果，例如 “Best Gen 1 heroes for Arena”。
- 时间同时说明动作，例如 “Verified 2 hours ago”。
- 演示数据必须写明 Prototype data。
- 综合热度写 Heat score，不写 Downloads 或 Revenue。
- 外部视频写明频道和 External video。
- 空状态提供一个可执行下一步。

## 9. 可访问性验收

- 页面只有一个 H1，标题层级连续。
- 所有交互有键盘焦点和可访问名称。
- 标签、状态和排名变化不只依靠颜色。
- 对话框打开后锁定焦点，关闭后返回触发按钮。
- 图片、图表和视频提供替代文本或摘要。
- 正文和控件对比度达到 WCAG AA。
- 200% 缩放时主要功能仍可操作。

## 10. 视觉验收清单

- 页面在 390×844、768×1024、1440×900 三种尺寸下检查。
- 无横向页面溢出。
- 导航、卡片、筛选、表格和正文使用统一令牌。
- 首屏内容密度达到对应模板要求。
- 无错误图片比例、跳动图片和被截断的关键标题。
- loading、empty、error 和 stale 状态均有设计。
